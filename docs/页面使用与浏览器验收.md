# 序会工作台 · 页面使用与浏览器验收

当前状态：P8 页面已实现，服务器端 HTTP、静态资源、JavaScript 模块及真实模型链路已验证。服务器未安装浏览器，以下浏览器项目尚未实测，不以自动勾选代替人工验收。浏览器验收作为 P9 的继续项。

## 打开页面

服务器终端：

```bash
conda activate demo1
cd /app/data/wjy/demo
bash scripts/run.sh
```

电脑通过 VS Code Remote 转发 8080，或执行：

```bash
ssh -N -L 8080:127.0.0.1:8080 用户名@服务器地址
```

在电脑浏览器打开 `http://127.0.0.1:8080/`。若当前 SSH 入口无法访问应用容器的回环地址，需要通过已有的容器端口转发访问 8080。不要直接双击 index.html，页面需要由服务提供 `/api` 与 `/static`。

页面依赖浏览器原生 ES modules、Fetch、EventSource、dialog 与 Intl；建议使用较新的 Chrome、Edge、Firefox 或 Safari。运行服务不需要 Node 或前端构建步骤。

- [ ] 系统开启减少动态效果后，不出现持续的角色脉冲动画。

## 完整操作链路

1. 点击“体验示例”，检查名称、日期 2026-10-21、参会人和正文填入。示例日期固定，如需测试当天会议可自行修改。
2. 点击“创建会议”，确认左侧档案新增会议，页面显示带编号原文；此时尚未分析或执行。
3. 点击“开始智能分析”，观察 Manager → Planner → Reviewer，运行失败需显示错误，成功仍应检查草稿状态。
4. 点击任务下的原文引用，确认定位到对应段落并高亮；Agent 事件不得展示模型内部思考文本。
5. 修改任务说明，确认出现“未保存”提示；保存按钮可用、复核和执行不可用。尝试离开当前会议，取消弹窗应保留输入。
6. 保存新版本，提交复核。若出现语义意见，先对照原文，必要时逐项填写理由再接受；不得直接忽略错误。程序硬错误不能接受。
7. 在版本下拉框查看历史，确认表单只读、不能执行；切回最新版本后恢复相应权限。
8. 在 ready 状态勾选核对声明，点击执行，再在弹窗确认。仅执行成功后正式看板出现任务；连续操作不得产生重复任务。
9. 将一个正式任务修改为“进行中”，再修改为“已完成”。刷新浏览器，状态与会议选择应恢复；指标与跟进页同步更新。
10. 按负责人筛选看板，检查截止日期预览。下载 JSON 与日历，检查文件实际到达下载目录；ICS 可导入日历查看全天截止日期。
11. 查看跟进页，检查完成、待办、逾期及未决议题；已完成项不算逾期。缺少日期的任务在日历导出提示中明确跳过。
12. 新建另一会议，粘贴正文；再新建并拖拽 TXT / 文本型 PDF，检查输入模式与文件名提示、失败后保留原输入。

## 异常与状态保护

- [ ] 无效或超限文件可读报错；不自动清空用户已填写的会议名称和正文。
- [ ] 在模型运行中切换会议，旧运行继续在后台执行，旧会议事件不出现在新会议。
- [ ] 运行时短暂断网，再恢复：进度重连、事件不重复，终态最终可通过查询恢复。
- [ ] 服务重启后，历史与已保存任务仍在；未完成运行显示中断，重试产生新运行。
- [ ] 两个浏览器标签页同时打开同一草稿：A 保存后 B 保存旧版本被拒绝；B 的本地修改保留，执行被阻止。
- [ ] 草稿有本地修改时刷新状态，修改不被覆盖；需要放弃时明确确认后才加载最新版本。
- [ ] 任务创建成功后，不能重新分析或改写已确认计划；状态仍可更新，JSON / ICS 下载可用。
- [ ] 错误包含可复制的请求编号或运行编号；不将失败显示成成功。
